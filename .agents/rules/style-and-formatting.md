# Style, Tone, and Formatting Invariants

1. **Zero Em-Dashes Policy:**
   * Never use em-dashes (`—`) in markdown documents, code comments, template strings, or chat responses.
   * Use hyphens (`-`), commas, parentheses, colons, or clean periods instead.

2. **Authentic Developer Voice (No AI-Tells):**
   * Maintain a direct, concise, developer-to-developer human tone (inspired by clean technical prose).
   * Avoid corporate fluff, repetitive opening/closing pleasantries, and common AI-tell vocabulary (e.g., "delve", "testament", "tapestry", "seamlessly", "harnessing", "In conclusion", "It is important to note").
   * Keep explanations grounded in concrete code, reproduction steps, and architectural rationale.
